马胖村单项体验模块

一、模块说明

1.1 模块定位

马胖村文旅项目需要一个“单项体验”模块，让用户可以像逛店一样自由选择村寨内的各类体验项目（家宴、住宿、手作、茶园等），按日期预约、加购、下单、到店核销。

1.2 整体业务

1.2.1 用户端

1.2.2 管理端

运营可维护项目、类别、价格、库存、详情内容、模块文案

1.2.3 后端

支持动态标签、差异化详情页、库存预占与释放

二、接口请求/返回格式规范

本模块所有接口统一使用 /api/v1/z_Ty/ 作为路径前缀，遵循以下格式。

2.1 请求格式

所有参数统一用 JSON 对象：

场景 参数类型 格式 示例
无参数 — 空对象 {}
单个标量参数 SingleInt / SingleString / SingleBoolean / SingleLong { "参数名": { "Value": 值 } } { "syGoodsId": { "Value": 3315 } }
两个及以上参数 ParaXxx 每个字段直接裸值 { "itemId": 1, "date": "2026-08-20", "quantity": 2 }

判定原则：

  1. 接口无参数 → 传 {}

  2. 接口只有 1 个标量参数 → 用 SingleXxx 包装 → { "参数名": { "Value": 值 } }

  3. 接口有 2 个及以上参数 → 定义 ParaXxx → 裸值对象

反例（禁止）：

*// ❌ 单参数裸传*
{ "syGoodsId": 3315 }
*// ❌ 单参数带 Value 但无参数名 key*
{ "Value": 3315 }
*// ❌ 多参数带 Value 包裹（多参数不包裹）*
{ "itemId": { "Value": 1 }, "date": { "Value": "2026-08-20" } }

正例：

*// ✅ 无参数*
{}
*// ✅ 单参数（SingleXxx）*
{ "syGoodsId": { "Value": 3315 } }
*// ✅ 多参数（ParaXxx）*
{
  "itemId": 1,
  "date": "2026-08-20",
  "quantity": 2
}

规则 说明

库存字段 stock（总库存）、sold（已售）、lockStock（预占）
可售余量 stock - sold - lockStock，后端计算

超时未支付（15分钟） 定时任务释放 lockStock
用户取消 释放 lockStock
退款 sold - quantity
并发控制 SQL Server 行锁 WITH (UPDLOCK, ROWLOCK)

五、数据库表设计

5.0 建表通用约定（遵循《项目开发规则》6.5–6.8）

  • 表名：保持 ty_ 前缀（规则 8.2 本项目专属约定），一表一脚本输出到 table/{表名}.sql，脚本结构按规则 6.8（IF EXISTS → DROP → CREATE → LOCK_ESCALATION → 主键 → 索引，段间 GO）。
  • 主键：统一 {域}{实体}Id int IDENTITY(1,1) 聚集主键，如 tyInfoId、tyItemId、tyOrderId；不用 GUID、不用复合主键。
  • 外键：不建物理外键，外键列直接沿用被引用表主键名（tyItemCategoryId、tyItemId、tyOrderId），并建普通索引。
  • 列名：统一 camelCase；布尔列 bit 用 is* 前缀（上架 isOnline、启用 isEnabled），订单状态拆分为 payStatus bit（是否支付）与 orderStatus int（订单状态流转）并存；排序列统一 orderSeq。
  • 类型：汇总/展示金额 decimal(18,2)，日历/明细单价 decimal(18,3)；中文字符串 nvarchar(n) COLLATE Chinese_PRC_CI_AS；URL/单号/编码 varchar；手机号 varchar(30)；长文本 nvarchar(max)。
  • 可空与默认值：除 payTime / checkinTime / updateTime / updateUserId 等可空审计字段外一律 NOT NULL；int 默认 0、金额默认 0、字符串默认 ''、启用/上架类 bit 默认 1。
  • 多公司隔离：主表必带 companyType smallint DEFAULT 0 NOT NULL（单项体验信息/类别/项目/价格日历/购物车/订单等独立业务表）；明细表、子表不带（订单明细、二维码表、标签汇总表、退改规则表），需要时通过关联主表的 companyType 过滤。
  • 标准审计字段：addTime datetime NOT NULL DEFAULT(GETDATE())、addUserId int NOT NULL DEFAULT(0)、updateTime datetime NULL、updateUserId int NULL DEFAULT(0)。
  • 索引命名：普通索引 IX_{表名}_{列名}，唯一索引 UX_{表名}_{列名}。

七、核心业务逻辑

7.1 动态标签生成规则

字段 规则 兜底
entry.tags 单项体验类别表前5个 name 不足5个时展示实际数量
entry.footerText 上架项目总数 + “项体验全年可选” N=0 时显示“暂未开放”
entry.minPrice 优先配置值，为空则查价格日历最低价 无数据时显示“—”
header.tags ["{N}项地道体验", "全年随心出发"] N=0 时显示“即将上线”

带 5 分钟缓存。

7.2 库存流转逻辑

创建订单（事务内）：

BEGIN TRANSACTION

1. 遍历 cartIds，对每个 (tyItemId, date)：
   SELECT stock, sold, lockStock 
   FROM ty_item_calendar_data WITH (UPDLOCK, ROWLOCK)
   WHERE tyItemId = ? AND date = ?
2. 校验：stock - sold - lockStock >= quantity
3. UPDATE ty_item_calendar_data SET lockStock = lockStock + quantity
4. INSERT INTO ty_order_data (payStatus=0, orderStatus=0, expireTime=now+15min)
5. INSERT INTO ty_order_item_data
6. DELETE FROM ty_cart_data WHERE tyCartId IN (...)
   COMMIT TRANSACTION

支付成功（幂等）：

BEGIN TRANSACTION

1. UPDATE ty_order_data SET payStatus=1, payWay=@payWay, orderStatus=1, payTime=now WHERE orderNo=? AND orderStatus=0
2. 对每个明细：UPDATE ty_item_calendar_data 
   SET lockStock=lockStock-quantity, sold=sold+quantity
   COMMIT TRANSACTION

取消订单：

BEGIN TRANSACTION

1. UPDATE ty_order_data SET orderStatus=6 WHERE orderNo=? AND orderStatus=0
2. 释放预占：UPDATE ty_item_calendar_data SET lockStock=lockStock-quantity
   COMMIT TRANSACTION

超时释放：定时任务每5分钟扫描 orderStatus=0 AND expireTime<now 的订单，置 orderStatus=2（过期未付款）并释放 lockStock。

退款：按订单 tyItemId 查 ty_refund_rule_data 表，根据距体验日期天数匹配 daysBefore 最大的规则，退款金额 = 订单总额 × refundRatio / 100；UPDATE ty_item_calendar_data SET sold=sold-quantity。

7.3 二维码核销逻辑

生成二维码：

1. 校验订单状态为"已支付"
2. 将该订单下所有未使用的码置 isUsed=1（作废旧码）
3. 生成新的 10 位随机码
4. 插入 ty_qrcode_data（addTime=now, expireTime=now+10min, isUsed=0）
5. 返回码给前端

核销：

1. 根据 qrcode 查询 ty_qrcode_data
2. 校验：存在、isUsed=0、expireTime>now
3. 根据 tyOrderId 查订单，校验订单状态为"已支付"
4. 返回订单明细给工作人员核对
5. 工作人员确认后：
   - UPDATE ty_qrcode_data SET isUsed=1, useTime=now WHERE tyQrcodeId=?
   - UPDATE ty_order_data SET orderStatus=5, checkinTime=now WHERE tyOrderId=?

异常处理：

场景 返回
码不存在 code=1, msg="无效二维码"
码已使用 code=1, msg="该二维码已核销"
码已过期 code=1, msg="二维码已失效，请重新生成"
订单状态异常 code=1, msg="订单状态异常"
